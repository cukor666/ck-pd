# ck-pd 密码管理器

基于 **Wails v2 + Go** 后端与 **Vue 3 + TypeScript + TailwindCSS** 前端的本地密码管理器。
所有数据在本地以强加密形式存储，不依赖任何云服务，**明文密码与密钥永不进入前端进程**。

| 分类 | 能力 |
| --- | --- |
| 保险库 | 主密码创建 / 解锁、手动锁定、闲置自动锁定、窗口最小化或失焦自动锁定 |

| 界面 | 中文界面、深色 / 浅色 / 跟随系统主题、列表排序模式、剪贴板状态提示 |

## 加密与安全设计

### 密钥层次

```
主密码
  │  Argon2id(password, salt, 64 MiB, 3 轮, 并行 4)
  ▼
KEK（密钥加密密钥，32 字节，仅存在于内存，用后立即清零）
  │  XChaCha20-Poly1305 解包
  ▼
DEK（数据加密密钥，32 字节随机，磁盘上只以被包裹的形式存在）
  │  XChaCha20-Poly1305 加密
  ▼
条目数据（JSON 载荷）
```

采用「双层密钥」而非直接用主密码加密数据，带来两个关键好处：

1. **更换主密码是 O(1) 操作**——只需用新 KEK 重新包裹同一个 DEK，条目数据完全不动，因此不会出现「改密码到一半失败导致数据全丢」的风险。
2. **主密码的暴力破解成本被 Argon2id 拉到最高**，而数据加密仍使用高速 AEAD。

### 磁盘文件格式（`.ckpd`，JSON 容器）

```jsonc
{
  "magic": "CKPD-VAULT",          // 固定魔数，错配直接拒绝
  "containerVersion": 1,          // 容器格式版本
  "vaultId": "<uuid>",            // 保险库标识
  "kdf": { "algorithm": "argon2id", "memoryKiB": 65536,
           "iterations": 3, "parallelism": 4, "keyLen": 32 },
  "salt": "<base64>",             // 16 字节随机盐
  "wrapAlgorithm": "xchacha20poly1305",
  "wrappedKey": "<base64>",       // DEK（含 24 字节 nonce 前缀）
  "payloadAlgorithm": "xchacha20poly1305",
  "payload": "<base64>",          // 全部条目（含 nonce 前缀）
  "checksum": "<base64>",         // 快速损坏检测（非安全边界）
  "updatedAt": 1700000000
}
```

**AAD 绑定**：`wrappedKey` 与 `payload` 在加密时都把
`magic + containerVersion + vaultId + KDF 算法与全部参数 + 算法名`
作为附加认证数据（AEAD AAD）。这意味着：

- 篡改盐或降低 KDF 参数（例如把 64 MiB 改成 16 MiB）→ 解密认证失败；
- 把一个保险库的密文塞进另一个保险库的文件头 → 解密认证失败；
- 位翻转或截断 → 解密认证失败。

校验和只用于快速发现「文件损坏」，不承担安全职责——真正的防篡改来自 AEAD 认证标签。

### 前端与后端的边界

这是本项目最重要的安全约束：

- **前端永远不持有密钥。** 密钥只在 Go 进程内存中，且仅在解锁期间存在。
- **前端永远不批量持有明文密码。** 绑定层返回的条目视图（`Summary` / `Detail`）在 Go 侧就把密码字段排除，序列化后不可能带上密码。
- **复制密码不经过前端。** `CopyEntryField(id, field)` 由 Go 读取明文并直接写入系统剪贴板，明文不进入 DOM、不出现在开发者工具、不进入任何前端存储。
- **显示密码需显式请求。** `RevealPassword(id)` 返回明文时同时返回**解锁代数（generation）**；前端渲染前必须校验代数未变化，否则丢弃结果——避免「解锁 → 显示 → 自动锁定」之后明文仍残留在界面上。
- **锁定时双向清理。** Go 侧锁定后清零 DEK 与条目的敏感字段，并通过 `vault:locked` 事件通知前端清空列表与详情；前端另有独立的闲置看门狗作为第二道防线。
- **不落任何日志。** 代码中不存在把密码、密钥、TOTP 密钥写入日志或错误信息的路径。

### 其它实现细节

| 项目 | 做法 |
| --- | --- |
| 随机数 | 全部来自 `crypto/rand`；生成器使用拒绝采样消除取模偏差（禁用 `math/rand`） |
| 原子写入 | 同目录临时文件 → `fsync` → `rename` 覆盖；任何时刻崩溃都不会留下半截文件 |
| 文件权限 | 类 Unix 下目录 `0700` / 文件 `0600`；Windows 下用 `icacls` 移除继承权限，仅保留当前用户 |
| 内存清零 | 派生密钥、DEK、明文载荷缓冲、主密码字节在使用后立即 `Zero`；锁定时逐条清零条目中的密码、备注与 TOTP 密钥 |
| 输入校验 | 严格拒绝非法 Base32；**不做** `0→O`、`1→I` 之类的「猜测式纠正」，避免把粘贴错误静默变成另一个合法密钥 |
| URL 处理 | 只允许 `http` / `https` 交给系统浏览器，防止 `javascript:` 等协议 |
| 前端存储 | 不使用 `localStorage` / `sessionStorage` / Cookie；设置项存于 Go 侧配置文件（不含任何秘密） |
| 依赖安装 | pnpm 默认拦截依赖的安装脚本，仅白名单放行 `esbuild`，降低供应链风险 |

## 威胁模型

### 能够防御

| 攻击场景 | 防护手段 |
| --- | --- |
| 磁盘 / 备份文件被窃取 | 全部数据为密文；无主密码无法解密 |
| 暴力破解主密码 | Argon2id（64 MiB / 3 轮）；离线爆破单次尝试成本极高 |
| 篡改或伪造保险库文件 | AEAD 认证标签 + AAD 绑定；任何改动都会导致解锁失败 |
| KDF 参数降级攻击 | KDF 参数被纳入 AAD，改动即认证失败 |
| 跨保险库密文替换 | `vaultId` 被纳入 AAD |
| 其它程序读取剪贴板 | 复制后自动清空剪贴板（默认 30 秒，可调或关闭） |
| 用户离开工位 | 闲置自动锁定 + 窗口最小化锁定；锁定时密钥清零 |
| 界面被肩窥或录屏 | 密码默认掩码；可开启「显示前二次确认」；显示后切换条目即隐藏 |
| 前端被注入脚本读取密码 | 前端根本不持有密钥；密码复制由后端完成 |
| 断电 / 崩溃导致数据损坏 | 原子写入 + 写前校验；失败时磁盘上仍是上一个完整版本 |

### 明确不防御

| 攻击场景 | 说明 |
| --- | --- |
| 操作系统被完全控制（键盘记录、内存转储、调试器附加） | 主密码输入与解锁后的明文都可能被截获。这是所有本地密码管理器的共同边界。 |
| 恶意软件读取剪贴板 | 只能靠缩短残留时间来缓解，无法根治。 |
| 内存换页到磁盘 | 取决于操作系统配置；程序未使用 `mlock`，无法保证密钥不被换出。 |
| 用户使用弱主密码 | 程序强制最低强度（评分 ≥「一般」），但无法从根本上阻止用户选择可猜测的口令。 |
| 侧信道（功耗、电磁） | 不在防护范围内。 |
| 忘记主密码 | **没有任何后门或恢复机制**。主密码丢失即数据永久不可读——这是设计取舍，不是缺陷。 |

## 构建与运行

### 一键构建（推荐）

```powershell
.\build.ps1              # 前端构建 + 绑定生成 + 测试 + 编译
.\build.ps1 -Run         # 构建后立即启动
.\build.ps1 -SkipFrontend -SkipBindings   # 只重新编译 Go 部分
```

产物位于 `build/bin/ck-pd.exe`（约 12 MB，已剥离符号表并以 GUI 子系统启动）。

### 关于 `wails build`

如果 Wails CLI 版本与本机 Go 工具链不匹配，`wails build` 会在绑定生成阶段报：

```
internal error: package "errors" without types was imported from "ck-pd/internal/securefile"
```

这是 **Wails 内置 Go 包加载器与新版 Go 标准库导出数据格式不兼容** 导致的，
与项目代码无关——`go build ./...`、`go vet ./...`、`go test ./...` 在同一环境下均正常通过。

`build.ps1` 因此采用的路径是：

1. `pnpm run build` —— 前端类型检查与打包；
2. `wails generate module` —— 生成 TypeScript 绑定（这一步是正常的）；
3. `go build -tags "desktop,production" -ldflags "-w -s -H windowsgui"` —— 直接产出 GUI 可执行文件。

若你的环境里 `wails build` 可用，直接用它也可以；两种方式产出的二进制等价
（syso 资源文件只影响图标与版本信息，不影响功能）。

### 生成 TypeScript 绑定

修改了 `app.go` 暴露的方法或 `internal/**` 中的数据结构后，必须重新生成绑定：

```bash
wails generate module
```

绑定位于 `frontend/wailsjs/`，**请勿手工修改**。

### 运行

```powershell
.\build\bin\ck-pd.exe
```

## 备份与恢复

### 导出

「设置 → 加密备份」：

1. 选择保存位置（可点「默认」使用带时间戳的默认文件名）。
2. 可选填写**备份口令**：
   - 留空 → 导出的是保险库容器副本，**用主密码解锁**；文件头可读，内容仍是密文。
   - 填写 → 在容器外再套一层 Argon2id + XChaCha20-Poly1305 加密，**需要备份口令 + 主密码两道密码**；适合上传到云盘或通过不可信通道传输。

### 恢复

「设置 → 从备份恢复」：

1. 选择 `.ckpd-backup` 文件；若受口令保护，程序会提示输入备份口令。
2. 程序会先校验容器结构，再在覆盖前自动生成当前内容的快照
   （`vault.ckpd.before-restore-<时间戳>`）。
3. 恢复完成后保险库回到**锁定状态**，请使用该备份对应的主密码解锁。

> 建议：把导出的备份与主密码分开存放。备份文件本身是密文，但
> **主密码 + 备份文件同时泄露 = 数据泄露**。

## 测试

后端包含覆盖核心安全属性的单元测试：

```bash
go test ./...
```

覆盖范围包括：

- 正确密码可解锁、错误密码被拒绝且不泄露信息
- 条目增删改查的持久化往返（锁定后重新解锁验证）
- **磁盘文件中不含明文片段**（标题与密码）
- **密文位翻转被拒绝**（且校验和自洽，证明拦截来自 AEAD 而非校验和）
- **KDF 参数降级被拒绝**
- **跨保险库密文替换被拒绝**
- 更换主密码后旧密码失效、数据完好、弱新密码被拒绝
- 备份往返（无口令 / 有口令）、错误备份口令被拒绝、恢复前生成安全快照
- 安全体检正确识别弱密码、空密码、重复密码，且**结果不含任何密码内容**
- 条目视图（`Summary` / `Detail`）序列化后**不含密码与 TOTP 密钥**
- TOTP 符合 **RFC 6238 标准测试向量**（SHA1 / SHA256 / SHA512）
- 非法 Base32 密钥被拒绝（不做静默字符纠正）
- 密码生成器的长度、字符类别、无重复、易混淆排除与位置分布

cd frontend && pnpm run typecheck && pnpm run build

## 已知限制

1. **无密码找回机制。** 主密码是唯一入口，丢失即无法解密。程序只提供「从加密备份恢复」这一条退路。
2. **强度评估是启发式的。** 使用长度 × 字符集的熵估算加规则惩罚，并非 zxcvbn 这类基于真实泄露口令库的模型；内置弱密码字典约 300 条。分值用于发现明显风险，不代表绝对安全等级。
3. **前端明文显示窗口有限但非零。** 用户主动点击「显示」时，明文会短暂存在于 WebView 的 DOM 中；切换条目、锁定或卸载组件时会清除。请配合「显示前二次确认」使用。
4. **剪贴板自动清除依赖程序存活。** 程序退出后，未到期的清除任务不会执行；此时请手动清空剪贴板。
5. **不使用 `mlock`。** 内存中的密钥可能被操作系统换页到磁盘，具体取决于系统配置。
6. **单文件保险库整体加解密。** 每次保存都会重新加密整个载荷。当前规模（数千条以内）无感知；条目数量极大时写入耗时会线性增长。
7. **未做多设备同步。** 设计目标是本地优先；多设备场景请通过加密备份手动迁移。
8. **Windows 之外的平台未实测。** 代码包含 macOS / Linux 的构建标签与权限处理，但仅在 Windows 上完成验证。
